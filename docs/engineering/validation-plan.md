# M1：引擎集成验证计划

日期：2026-10-13。状态：验证计划已整理并转为 [可执行规格](../specs/README.md)，下列验证均未执行；本次仅发布规格，尚未开始实现。

依据：[23 项已确认选择](../product/requirements.md)、[架构方案](architecture.md)、[固定版本源码调查](../research/fsearch-engine.md)。初始上游基线为 `88e63fdf850cf7749deae8198b187accd21f8ba5`（0.2.1），并保留后续升级路径。

## 目标与交付

证明公开 Fsearch Engine 能以薄适配层支撑已确认的 v0.1 行为，先得到真实查询和可复现证据，再实现完整 alpha 界面。

M1 交付：项目内 Rust/Swift 集成骨架、最小原生验证窗口、受控样本与关键契约测试、桥接协议说明、性能与资源报告、架构结论，以及可验证的双架构构建和上游升级检查基础。它们不等于 alpha 或公众安装包已经完成。

## 环境边界

- 所有依赖、缓存、产物和测试文件保存在项目内；不更改全局工具链，不运行 `fsearch install`。
- 首批查询测试使用上游公开 Index/Query/Searcher 的合成样本及项目内文本 fixture；测试 Searcher 通过不等于真实 Engine 已验证。
- Engine 没有索引 root 参数。`home`、`dir` 和查询 `in:` 不能当成限制全盘扫描的保证；启动真实 Engine 前先证明测试限制策略有效，或使用专用测试环境。未具备边界时，该项记录为待验证，继续其他独立工作。
- 数据目录与已有 CLI 索引区分，不读取或迁移用户已有索引，不终止外部进程。真实覆盖、TCC 和 iCloud 行为放在专用安装验证环境。
- 签名凭据准备是正式签名/TCC 验证的外部前置条件，缺失时先做编译与开发验证，不标记对应门禁通过。
- Intel 编译目标在隔离构建环境准备；本机只有 arm64 target 时不全局安装新 target。跨编译、Rosetta 与 Intel 实机分别记录。

## 样本与记录口径

受控样本包含中文、emoji、NFC/NFD、大小写、空格/冒号/引号/换行、长路径、同名文件、隐藏项、目录、应用包和符号链接。名称自然排序包含 `文件2` / `文件10`；大小验证包含 2 GiB 编码边界，避免实际分配数 GiB 文件，可先使用合成索引值，文件属性读取另用小型或适当的稀疏 fixture 验证。

性能逐步增加规模：25,001、100,000、1M，再评估 8M 合成条目。记录数据规模、路径长度、匹配率、冷/热状态、设备、架构、OS、工具链和命令，以及首屏/完整排序 p50/p95、RSS 峰值、索引体积和空闲 CPU。合成索引压力测试与真实首次扫描分开，不能相互替代。

PRD 的 warm 首屏 p95 ≤150ms 是候选目标，尚无客户端实测。全局排序允许异步，不能用“关联性前几十条很快”推导完整排序也很快；资源不可接受时记录测量结果和方案代价，再决定优化或上游改进。样本、运行次数与测试状态都要可追溯，不把未验证项写成通过。

## 通过与失败处理

- 完整集合正确、无伪造精确总数，符合自然排序与索引大小的约定；分页及刷新没有混入不同快照。
- 桥接、线程和生命周期有真实验证；两种架构、最低 OS 与权限项分别标注已验证/未验证。
- 资源报告公开默认内容索引的成本；必要补丁有来源、测试和移除条件，并能重新评估升级。
- 技术验证失败时先给出根因，不通过限制条数、改为当前页排序或另建搜索引擎来假装满足需求。同一方法失败两次按仓库规则停止小修，提出不同方案和代价并确认。
- 嵌入路线不成立时单独提出 helper 方案，不静默切换；仍保留 Fsearch 为引擎，验证 helper 的 TCC、生命周期、签名及 IPC。

M1 的核心技术门禁未通过前，不将 alpha 功能标成完成。缺少签名/设备等条件允许继续独立的开发验证，但最终报告必须保留这些未验证项。
