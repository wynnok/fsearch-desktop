# T28：开发包签名、公证与最终校验链路

对应 [GitHub #42](https://github.com/wynnok/fsearch-desktop/issues/42)，父规格 [SPEC-10](../specs/10-public-release.md)。用户确认暂时没有签名凭据，先实现链路并保留门禁。**本票尚未完成真实签名、公证或干净系统验收。**

## 输入与安全边界

先用项目已有入口构建和验证开发 DMG，输入为其 staging `.app`。维护者须在安全环境预先提供可用的 Developer ID Application 身份和 notarytool Keychain profile；脚本只引用身份/profile，不收集密码、私钥、API key，不导入证书或修改任何 keychain。

```sh
bash scripts/package-dev-dmg.sh
bash scripts/verify-dev-dmg.sh --dmg <development-dmg>

# 以下是身份/profile 名称占位符，不是私钥或密码。
FSEARCH_SIGNING_IDENTITY='Developer ID Application: YOUR_IDENTITY' \
FSEARCH_NOTARY_PROFILE='YOUR_KEYCHAIN_PROFILE' \
bash scripts/notarize-dev-app.sh --app '.build/dev-dmg/package/Fsearch Desktop Development.app'
```

缺凭据立即退出，不尝试签名或网络上传。每次执行创建独立的 `.build/signing/run.*`，权限 0700，原始应用不变。失败时留下失败阶段、候选应用/DMG及允许字段的公证摘要；临时原始工具输出、上传 ZIP 和挂载/安装工作区清理，不回显账户信息或凭据。公证摘要仅保留合法 UUID 和已知状态；网络失败/响应损坏保留 unknown，不能当成功。

## 执行顺序

1. 校验开发包标志、主程序 Universal 架构、许可证、构建记录、受控样本和源签名；确认现有身份确属 Developer ID Application。
2. 复制输入，签名前将包状态改为签名验证版，并移除旧的 FsearchNotarized 声明。此后不改变应用资源/元数据；公证证据由最终报告记录。
3. 先签各 Mach-O，再按深度签嵌套 bundle，最后签主应用；带 secure timestamp 和 Hardened Runtime，核对主签名 Authority/runtime/timestamp 与严格验证。
4. ZIP 提交应用，要求真实 notarytool 成功退出、合法 submission ID 和 Accepted；staple/validate 应用，再执行 spctl。
5. 将已 staple 应用封入独立开发验证 DMG，签名 DMG，再提交并等待 Accepted、staple/validate 和 codesign/spctl/hdiutil 校验。
6. 只读挂载最终 DMG，安装到项目临时 Applications，重新校验应用签名、ticket 和 Gatekeeper；运行安装后的受控搜索/文件旅程并正常退出。共用开发包冒烟入口，有 180 秒超时与本次子进程清理。
7. 卸载挂载点后才生成最终 SHA256SUMS 和验证报告。任何失败不生成成功报告；不创建版本 tag、自动合并或上传 GitHub Release。

成功状态只表示当前机器的本地签名产物校验通过，报告仍明确标记干净系统、Intel 实机和 macOS 13 未验证。它不是 T29 的公众发行，也不是完整 alpha 验收。

## 本次验证

`scripts/tests/test-notarize-dev-app.sh` 通过命令入口控制外部工具，覆盖缺凭据、签名失败、网络失败、损坏响应、公证 Invalid、staple 失败和 Gatekeeper 拒绝。每个失败均核对非零退出、无成功报告/最终哈希、原始输入未改、临时目录清理及私密原始输出缺失；公证拒绝保留合法 ID/状态且不继续 spctl。测试由 SigningValidationTests 纳入 XCTest。

另用实际受控进程拒绝 TERM 验证清理：先观察到原清理无界等待失败，再改为 TERM 后等待至多 3 秒、必要时对本次 PID 发 KILL 并回收。回归通过，超时不会因进程忽略 TERM 而继续无限等待；独立 watchdog 保护测试本身，样本和子进程清理。

这些工具替身只证明失败门禁，不能证明真实 Developer ID、公证服务或 Gatekeeper 成功。未进行凭据收集、Apple 上传、真实签名、公证 Accepted 或干净系统安装；外部门禁保持未通过。

依据：[Apple 公证流程](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)、[公证要求](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)，以及本机 `xcrun notarytool submit --help` / `xcrun stapler` 的实际选项。
