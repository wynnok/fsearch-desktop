## 公开契约

新增名称模式服务边界：

- `NameMatchMode`：`contains`、`fuzzy`、`prefix`、`suffix`、`wholeName`。
- `SearchMode.fuzzy`：additive 的桥接传输模式，不改变已有 `contains` / `advanced` 请求。
- `NameSearchRequest`：持有原始查询与模式，不把普通输入拼接成高级查询语义。
- `FsearchService.snapshot(_:sort:maximumResults:)`：名称模式查询复用既有 actor、真实服务、完整快照和分页。
- `SnapshotQueryController.query(_:sort:...)`：在主线程统一应用模式默认排序；显式用户排序优先。
- `NameSort.relevance`：保留上游关联性顺序，不执行客户端二次排序；名称、大小和修改时间仍使用既有全局机械排序。

包含模式继续使用桥接已有的结构化不区分大小写名称包含匹配。前缀、后缀和完整名称在 Swift 服务边界生成经过转义的 Fsearch `re:` 查询，并同时覆盖 NFC/NFD；匹配仍由固定上游执行。

`bridge/src/lib.rs` 的 `SearchMode::Fuzzy` 不调用 `Query::parse`。桥接按空白切词，直接构造上游公开 `fsearch::Query` 的 `Token`：ASCII 小写、`Mode::Fuzzy`、按长度计算 0/1/2 个 typo edits，并填写 `mask`、`rest`、`start`。`:`、`*`、引号、`!`、`^`、`$` 等均作为 token 字节数据。POSIX 文件名不能包含 `/`，因此单个空白词中的 `/` 仅用于把结构化路径分量逐个 fuzzy 匹配；它不启用 `Query::parse` 的 filter、glob、negate、prefix、suffix、scope、under 或 path 指令。不同 Unicode 规范化形式作为 `Query.alt` token 保留。未修改 `Cargo.toml`、`Cargo.lock`，未复制匹配、评分或分页算法。

窗口状态按边界拆分，`SearchModel` 只作为组合根：

- `SearchConfiguration` 持有查询、名称模式和用户显式排序，不依赖选择或 UI。
- `SnapshotQueryController` 持有结果、快照、phase 和分页位置，继续负责旧请求隔离。
- `SearchSelectionState` 持有结果路径选择和检查器可见性；切换检查器或选择不修改搜索配置。
- `SearchModel.activity` 与控制器 phase 共同区分查询、排序、错误、无匹配、部分结果和分页状态。
- 空输入或纯空白输入在控制器调用前停止，清空当前快照并显示提示，不查询全部文件。

SwiftUI 负责配置区、状态区和检查器组合；AppKit `NSTableView` 负责高密度结果列、原生列头排序和键盘行选择。原生“搜索”菜单提供聚焦、查询、刷新、取消和检查器切换；结果列包含名称、位置、索引大小和修改时间。
