# T10：原生主窗口与名称模式

对应 [GitHub #24](https://github.com/wynnok/fsearch-desktop/issues/24)。本票实现完整原生主窗口、五种名称模式、真实结果分页与检查器接缝，并为后续 T11-T18 固定搜索配置、选择、排序和检查器状态边界。样本模式与未通过 M1 外部门禁的构建仍明确标为非 alpha。

## 公开契约

新增名称模式服务边界：

- `NameMatchMode`：`contains`、`fuzzy`、`prefix`、`suffix`、`wholeName`。
- `NameSearchRequest`：持有原始查询与模式，不把普通输入拼接成高级查询语义。
- `FsearchService.snapshot(_:sort:maximumResults:)`：名称模式查询复用既有 actor、真实服务、完整快照和分页。
- `SnapshotQueryController.query(_:sort:...)`：在主线程统一应用模式默认排序；显式用户排序优先。
- `NameSort.relevance`：保留上游关联性顺序，不执行客户端二次排序；名称、大小和修改时间仍使用既有全局机械排序。

包含模式继续使用桥接已有的结构化不区分大小写名称包含匹配。前缀、后缀和完整名称在 Swift 服务边界生成经过转义的 Fsearch `re:` 查询，并同时覆盖 NFC/NFD；匹配仍由固定上游执行。模糊模式使用上游既有 fuzzy 词法，默认关联性；其它模式默认名称自然升序。本票未修改 `bridge/**`，未复制索引、匹配、评分或分页算法。

窗口状态接缝集中在 `SearchModel`：

- `query`、`nameMode` 和可空的 `sortPreference` 分别表示搜索配置与用户显式排序。
- `selection` 以结果路径作为稳定选择标识；检查器只读取当前选中结果。
- `isInspectorVisible` 控制检查器区域，不触发新查询。
- `activity` 与控制器 phase 区分查询、排序、错误、无匹配、部分结果和分页状态。
- 空输入或纯空白输入在控制器调用前停止，清空当前快照并显示提示，不查询全部文件。

SwiftUI 负责配置区、状态区和检查器组合；AppKit `NSTableView` 负责高密度结果列、原生列头排序和键盘行选择。原生“搜索”菜单提供聚焦、查询、刷新、取消和检查器切换；结果列包含名称、位置、索引大小和修改时间。

```bash

bash scripts/dev.sh check
bash scripts/dev.sh test
```
