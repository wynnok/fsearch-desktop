# T32：内容预算续查与 Unicode 高亮

对应 [GitHub #46](https://github.com/wynnok/fsearch-desktop/issues/46)。固定上游为 `0.2.1 / 88e63fdf850cf7749deae8198b187accd21f8ba5`。

## cursor 与未完成语义

- `ContentSearchRequest.cursor` 是独立的内容字段，bridge 只将它映射到 `Grep.skip`；名称查询继续使用 `SnapshotCursor`/offset，两者没有复用。
- `ContentSearchController` 在首次查询和继续查询之间保留当前请求与 generation。继续查询只在存在 `next` 时发起；新查询、选项变化或晚返回会推进 generation，旧续查不能覆盖新结果。
- 状态同时考虑 `complete`、`next`、`indexed` 与请求预算：有 cursor 显示“可继续”，缺少 cursor 但未完成显示停止/可能不完整，完成且有 cursor 也不显示为全部匹配。文件和已显示正文匹配数分开累计。

## Unicode 高亮

- `ContentLine.nativeRanges` 将上游 UTF-8 byte ranges 转为 `Range<String.Index>`；边界落在多字节标量内部时向外贴齐，超出截断片段的尾部安全裁剪。组合字符、emoji、中文和截断范围由 `ContentPaginationTests` 覆盖。
- 内容窗口使用 `AttributedString` 标记 native ranges；没有把字节偏移直接当 SwiftUI 字符位置。

## 验证

- `ContentPaginationTests` 通过独立 loader 验证内容 cursor、无 cursor 停止状态、late continuation 隔离和 Unicode range 转换。
- 真实受限 Engine 的 `ContentCheck` 以 `limit=1` 获取两页以上内容结果，核对 cursor 不重复、最终覆盖全部受控文件；原生内容 smoke 开启小页限制并调用“继续”，确认界面累计结果显示。
- `bash scripts/dev.sh check`、targeted tests 和 `bash scripts/content-validation.sh` 通过。

## 边界

内容结果仍受上游每文件行数、片段字节数、文件限制和时间预算约束。`complete` 可能表示本页达到文件限制而不是全部匹配已展示，界面按 cursor 语义显示部分状态。
