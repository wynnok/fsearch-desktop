# T03：完整名称快照与分页

实施票据：[TICKET-03：完整名称快照支持自然排序和跨页浏览](https://github.com/wynnok/fsearch-desktop/issues/17)。

## 公开契约

`FsearchService.snapshot(_:sort:maximumResults:)` 默认通过同一 Fsearch Searcher 取得受控样本索引的完整匹配集合。`NameSnapshot` 持有不可变结果，名称使用 macOS `localizedStandardCompare` 自然比较，等价名称按绝对路径 UTF-8 字节次序打破平局；降序同时反转名称和路径次序。

`NameSnapshot.id`、`requestID`、`sort`、`loadedCount` 和 `isComplete` 标识查询与完整性。`totalCount` 仅在服务明确证明集合完整时有值。显式 `maximumResults` 使用有界查询；不完整集合只能称为已载入排序。

`page(after:pageSize:)` 只复制所需页，提供 `SnapshotPage.results`、`nextCursor`、`snapshotID`、`requestID`、`isComplete` 和 `totalCount`。游标只能在所属快照使用，跨快照游标抛出 `SnapshotError.foreignCursor`；页大小必须大于零。刷新、改查询、改排序建立新的 UUID；已有快照仍是其原始不可变集合，不与新页混合。

## 验证接缝

沿用用户确认的 Swift 公开 `FsearchService` 接缝，真实文件通过 C ABI 与上游 Searcher，不模拟匹配或检查私有索引结构。首个自然名称测试先因缺少 `snapshot` 编译失败，新增契约后通过。后续同名子目录测试先暴露原单层样本列表无法返回子目录文件，再由 T02 的受控递归样本扫描转绿。

25,001 个真实文件以倒序创建，通过每页 317 条读取全量，与独立的整数 1…25,001 对应路径逐项比较，并验证无重复、精确完整总数。测试生成的目录限定在项目 `.build/snapshot-fixtures`，每次测试退出时清理。

六个 `NameSnapshotTests` 逐片验证：完整数字自然排序与计数；大样本跨页集合；大小写、重音、中文、emoji、NFC/NFD 和同名路径的升降序；刷新/查询/排序变化的快照隔离；部分集合的诚实计数；空集合与非法页大小/限制。刷新测试实际新增/删除样本文件，确认旧快照继续返回原来的页，三个新快照均拒绝旧游标。部分集合测试明确覆盖短末页且无 `nextCursor` 时仍不能展示完整总数。

单测复现：`bash scripts/dev.sh test --filter NameSnapshotTests`。100,000 复现：`FSEARCH_SNAPSHOT_COUNT=100000 bash scripts/dev.sh test --filter NameSnapshotTests.testCompleteLargeSnapshotHasIndependentNaturalOrderAcrossPages`。两组大样本均通过逐路径完整集合比较，默认测试保持 25,001；没有在源码中写死旧 JSON 上限作为集合边界。

原生窗口提供名称升降序、同一快照继续载入和显式刷新。输入/模式/排序改变会撤销当前快照，generation 检查拒绝晚返回覆盖新条件。原生冒烟以每页 2 条跨三页核对独立数字顺序，展示完整总数与最终升降序；另外验证显式限制的“部分结果/总数未知”，以及新增文件后的新快照和新总数。截图在项目 `.build/native-smoke/`，生成的临时样本在退出前清理；这里只使用样本 Searcher，不启动真实 Engine。

## 资源测量

测量设备为本机 Apple arm64、Debug 构建；首次为新建服务后的第一查询，未清除操作系统文件缓存。初始化包含受控根的样本扫描和索引建立；快照耗时包含查询、FFI JSON、Swift 解码和名称全量排序。热查询连续执行 5 次，p50 为中位数，p95 为 nearest-rank 第 5 项，样本数不足以作稳定性能承诺。

| 文件数 | 初始化秒 | 首次快照秒 | 热 p50 秒 | 热 p95 秒 | XCTest 进程峰值 RSS 字节 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 25,001 | 0.141 | 3.333 | 3.275 | 3.310 | 89,276,416 |
| 100,000 | 0.751 | 14.973 | 14.906 | 15.631 | 284,459,008 |

RSS 使用 macOS `getrusage(RUSAGE_SELF).ru_maxrss`，为整个 XCTest 进程的累计高水位，包含测试运行器、文件名/期望路径数组、桥接与快照，不是单个快照的独占内存。文件创建与清理不计入上述查询时间，但属于进程 RSS 范围。

最终联合套件共 20 项通过、0 失败。其中 25,001 回归再次核对完整集合：初始化 0.174 秒、首次 3.217 秒、热 p50 3.179 秒 / p95 3.226 秒，套件进程当时峰值 RSS 146,817,024 字节。该运行还包含 T01/T02 测试与更早分配的高水位，不与表中单独大样本运行的 RSS 直接作同范围比较。

完整名称排序仍有可观察等待时间。此票只验证样本 Searcher；真实 Engine 生命周期、1M/8M 阶段、双架构、大小/修改时间排序由后续票据验证，不能把本机结果外推为生产索引承诺。
