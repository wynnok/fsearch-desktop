# T04：索引大小与修改时间全局排序

对应 [GitHub #18](https://github.com/wynnok/fsearch-desktop/issues/18)。在 T03 完整不可变快照之上，公开 `NameSort` 新增 `sizeAscending`、`sizeDescending`、`modifiedAscending`、`modifiedDescending`；原名称排序 API 保持兼容。比较上游返回的索引字段，同值按绝对路径 UTF-8 字节稳定排序，降序同时反转字段与路径次序，再对同一快照分页。

原生窗口提供名称、索引大小和修改时间列头，点击切换升降序并发起异步查询。完成状态显示实际字段和方向，部分集合仍仅报告已载入排序。索引大小说明明确不代表当前真实字节、目录汇总或磁盘占用。

## 验证

用户确认的 Swift 公开服务接缝使用真实受控文件，经 C ABI 调用固定上游，无模拟元数据。第一条 size 用例因缺少枚举值编译失败；实现后，三项 `SizeTimeSnapshotTests` 于 2026-10-13 全部通过：

- 五个文件以两条一页核验大小/修改时间升降序及同值路径稳定性。
- 稀疏文件覆盖 2 GiB 前一字节、边界、边界后一字节及下一 2 MiB 档；独立预期索引值为 2147483647、2147483648、2147483648、2149580800。
- 同一公开查询按上游大小筛选，确认边界后一字节按索引取整值匹配，而不读取实际大小替代上游语义。

`bash scripts/dev.sh test --filter SizeTimeSnapshotTests` 可复现。稀疏文件位于项目 `.build/size-time-fixtures`，用例退出清理，不实际分配数 GiB 内容。

原生 `ui-smoke` 已逐一通过四个新增排序方向，跨所有页比较独立预期文件名，并截取对应列头与完成状态。性能和并发行为见 [T05](T05.md)。此票不代表真实 Engine、双架构和最低系统门禁通过；各自见 T06/T07。
