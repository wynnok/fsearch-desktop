# T05：长查询与排序期间输入保持可用

Ticket：[TICKET-05](https://github.com/wynnok/fsearch-desktop/issues/19)。

`SnapshotQueryController` 是原生 UI 使用的公开请求边界。查询、排序或条件变更会取消旧任务并递增请求代次；晚返回的旧快照无法写入结果、总数或分页位置。正在处理时保留旧行供选择，立即清除旧快照和分页位置，状态文字明确旧行不是当前最终结果。查询按钮、输入框、排序列头与窗口保持可用；取消、失败或部分结果均可再次发起正常查询。

`FsearchService` actor 执行引擎查询与完整集合排序，`SnapshotQueryController` 在主线程发布完成后的快照和首个页面。取消会停止结果发布；已进入不可中断的原生引擎调用仍需返回，UI 不等待该调用完成才接受新输入。

验证接缝采用用户确认的公开 Swift 服务、真实原生窗口与最终产物。`QueryResponsivenessTests` 使用真实服务生成结果，仅在服务响应外安排快慢顺序，覆盖旧结果/计数/分页隔离、处理中保留选择所需旧行、部分结果总数未知、失败与取消后的恢复。第一条用例先因缺少公开 controller 编译失败，再实现并通过。

`bash scripts/dev.sh ui-smoke` 可选原生验证创建项目 `.build/native-smoke` 内的受控 25,001 个文件，执行完整快照查询，通过真实 `NSTextView` 在处理中更改输入，验证新计数与分页不被旧请求覆盖，同时处理窗口显示与缩放。主线程每 10 ms 记录心跳，记录实际最大间隔及进程峰值 RSS，并将结果写入 `responsiveness.txt`。可以通过 `FSEARCH_SNAPSHOT_COUNT` 增大集合；测试完移除本次创建的受控文件。

本票的实测集合为 25,001 个真实文件；它验证请求隔离、输入可用性和资源记录方式，不宣称完成父 SPEC-02 的 1M 逐级测量与 8M 评估。更高规模门禁继续由父规格跟踪。

原生界面同时展示 T04 的名称、索引大小和修改时间列头及方向、全局排序完成状态，并说明索引大小精度和变化滞后。
