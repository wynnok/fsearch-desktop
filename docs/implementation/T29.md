# T29：已批准 tag 的签名、公证与发布链路

对应 [GitHub #43](https://github.com/wynnok/fsearch-desktop/issues/43)。本次用户明确要求继续 T29/T30 代码实施，保留 [T27](T27.md) 与 [T28](T28.md) 未通过的验收门禁；本票没有真实发行成功记录。

## 发布顺序与失败边界

`.github/workflows/release.yml` 仅响应 `v*` tag push，严格预检只接受 `vMAJOR.MINOR.PATCH`。普通分支 push 不进入发布。构建/签名 job 默认只读权限，只有后续 publish job 有 contents:write；action 均锁定 commit SHA，按 tag 串行且不取消已运行作业。

1. release environment 中的维护者批准记录必须对应当前 tag 和 checkout commit，明确真实 Engine 默认模式，并附 T27、T28、Intel、macOS 13、TCC、干净安装、上游升级及 CI 下载证据。任一缺失/未通过停止。版本发布说明 `docs/releases/<tag>.md` 必须已在该提交中存在。
2. 项目内准备既有 Rust 1.99.0 / 两 target；复用 pin、check、完整测试、开发包构建与实际安装 verifier。
3. `sign-release-ci.sh` 仅在 CI 使用临时证书/API key/keychain，明确 keychain 参数，不改默认 keychain 或全局 search list；输出与凭据不回显，退出清理。复用 T28 的真实 notarytool Accepted、合法 ID、staple、codesign/spctl 和安装链路。
4. 签名前把应用标识/名称/包状态固定为 release candidate，版本必须与构建一致；签后不再修改资源。最终 DMG、SHA256SUMS、公证摘要、验证报告、第三方许可及批准记录进入 artifact。
5. 第二个 macOS job 下载已签 artifact，重新预检批准和哈希，创建**新 draft** Release；`--verify-tag` 禁止隐式创建 tag，既有 Release/draft 不复用、不覆盖。
6. 从 GitHub 下载 draft 资产，`verify-signed-release.sh` 核对哈希、commit/version/引擎、许可、Universal、真实 ticket/Gatekeeper，复制到项目临时 Applications 并跑原生样本旅程和退出。上传下载/安装证据后，才将本次新 draft 发布。此前失败保留未公开 draft/安全失败摘要，不删除历史或自动重写 tag。

本机安装不能替代 Intel、最低系统或真实 TCC；这些依赖维护者提供并审核同 commit 的真实证据。批准 JSON 是维护者的证据声明，预检校验字段/绑定关系，不会访问链接代替人工验证，也不会把字段 true 当成设备测量。仓库维护者必须预先配置 release environment 的 required reviewers、tag 限制、变量和 secrets；仅写 environment 名称不会自动建立这些保护。本任务未更改仓库环境权限或配置。

## 外部配置

release environment 的变量：`RELEASE_APPROVAL_JSON`、`FSEARCH_SIGNING_IDENTITY`。

凭据仅安全配置为 environment secrets：`FSEARCH_CERTIFICATE_BASE64`、`FSEARCH_CERTIFICATE_PASSWORD`、`FSEARCH_NOTARY_KEY_BASE64`、`FSEARCH_NOTARY_KEY_ID`、`FSEARCH_NOTARY_ISSUER`。不提交私钥/证书，不向聊天提供秘密值。CI 临时文件位于项目 `.build/signing-ci/run.*`，原始输出结束删除；失败只保留脱敏阶段/公证 ID/状态。

批准记录公开契约：

| 字段 | 要求 |
| --- | --- |
| schemaVersion | 1 |
| tag / sourceCommit | 精确 tag 与完整当前 commit |
| approved / defaultMode | 维护者明确批准 true；实际默认模式 engine，样本模式不合格 |
| gates | t27、t28、intel、macos13、tcc、cleanInstall、upstreamUpgrade、ciDownload 全部存在 |
| 每个 gate | result=passed、sourceCommit 同当前 commit、url 为本仓库 Actions run/Issue/PR 证据链接 |

没有生成可用于真实发布的批准文件、版本说明或 tag。测试里的人工记录是受控 fixture，只证明门禁解析，不用于发布。
