# T22：两架构开发 DMG 与 push/PR 验证

对应 [GitHub #36](https://github.com/wynnok/fsearch-desktop/issues/36)，父规格 [SPEC-09](../specs/09-development-packages.md)，交叉验收覆盖 [SPEC-04](../specs/04-dual-architecture.md)。本票只提供未公证的开发验证包；它不是稳定发行、不是已公证包，也不解除 Intel Mac 与 macOS 13 实机门禁。

## 可复现入口

在项目根目录运行：

```sh
bash scripts/check-upstream-pin.sh
bash scripts/dev.sh check
bash scripts/dev.sh test
bash scripts/package-dev-dmg.sh
bash scripts/verify-dev-dmg.sh --dmg .build/dev-dmg/output/*.dmg
```

`check-upstream-pin.sh` 以 `bridge/Cargo.toml` 为单一期望 pin，校验 `bridge/Cargo.lock` 中的 Fsearch source/version 与 `bridge/src/lib.rs` 的内嵌版本一致。

`package-dev-dmg.sh` 复用 `scripts/architecture.sh build all release`，把两个已分别验证的实现合并为 Universal `.app`，写入开发状态、客户端版本、上游 Fsearch 版本/commit、runner image、工具链、许可证和构建记录。Cargo 依赖通过项目内 `cargo metadata` 和本地 registry cache 生成 `THIRD-PARTY-NOTICES.txt`；任一依赖缺少许可证文本时打包失败。生成：

- `.build/dev-dmg/output/Fsearch-Desktop-<version>-dev-<commit>-universal.dmg`
- `.build/dev-dmg/output/build-manifest.txt`
- `.build/dev-dmg/output/SHA256SUMS`
- `.build/dev-dmg/output/THIRD-PARTY-NOTICES.txt`

`verify-dev-dmg.sh --dmg <path> [--manifest <path>] [--sha256sums <path>]` 接受项目外只读 DMG，不写 DMG 所在目录；报告和冒烟日志固定写入项目 `.build/dev-dmg/verification/`。它校验 DMG 结构、Applications 安装入口、主程序 Universal 架构、系统动态依赖、版本/开发状态、全部许可证、构建记录、ad-hoc 签名和最终 SHA-256；随后把应用复制到临时 Applications 目录，启动已安装应用，执行现有 `--smoke` 查询/排序/分页/响应性套件并等待正常退出。只有全部检查通过时才写 `verification-report.txt`。

## GitHub Actions

`.github/workflows/dev-dmg.yml` 只响应工作分支 push、PR 和手动触发；tag push 不匹配该 workflow，正式 `v*` tag 仍由公众签名公证发行分路处理。工作流把固定 Rust 1.99.0 与两个 target 准备到项目 `.build/rustup-home`，运行 pin 检查、`dev.sh check`、`dev.sh test`、打包和安装验证，成功后上传 DMG、manifest、SHA-256、第三方 notices 和运行验证报告；任一步失败都不会到达上传步骤。工作流不创建 Release、不运行 CLI install、不修改系统隐私设置，也不引用签名凭据。

## 本机验证

2026-10-13 在 Apple Silicon arm64、macOS 27.0.1 (26A434)、Rust 1.99.0、Swift 6.4、Xcode 27.0 环境执行。

```sh
bash scripts/check-upstream-pin.sh
bash scripts/dev.sh check
FSEARCH_DEV_RUST_VERSION=1.99.0 bash scripts/package-dev-dmg.sh
bash scripts/verify-dev-dmg.sh --dmg .build/dev-dmg/output/*.dmg
```

- 上游 pin 检查：正向通过；将 lock 中 revision 改错后按预期失败。
- `dev.sh check`：Rust check、双架构所需的 Swift 构建与现有链接检查通过。
- 第三方 notices：从锁文件生成 24 个第三方 package 的许可证文本；缺少许可证文本的合成依赖按预期失败，没有静默缺项。
- 打包：`architecture.sh build all release` 的 arm64/x86_64 两轮构建和 `verify-artifact.sh` 均通过；合并应用后生成 DMG、manifest、notices 与 `SHA256SUMS`。
- 安装验证：DMG 结构、Applications 入口、Universal 主程序、系统动态依赖、版本/开发状态、项目/Fsearch/第三方许可证、构建记录、ad-hoc 签名与最终 SHA-256 均通过。
- 外部只读副本：把 DMG、manifest 和 SHA256SUMS 放到项目 `.build` 之外并设为只读后，使用显式 `--dmg/--manifest/--sha256sums` 再次完整验证通过；验证目录未新增文件，报告仍写入项目 `.build/dev-dmg/verification/`。
- 真实安装路径：应用从挂载 DMG 复制到临时 Applications 目录后启动，执行 21 个现有 `--smoke` 查询/排序/分页/响应性状态并正常退出。
- 运行证据：arm64 原生进程；明确没有把本机运行解释为 Intel Mac 或 macOS 13 门禁通过。

完整 XCTest 在 `/private/tmp/fsearch-desktop-t22` 直接运行时，33 项中 32 项通过；`IndexResourceTests.testSyntheticReportDoesNotClaimDefaultIndexCost` 因 worktree 位于 `/private/tmp` 失败。根因是 Foundation 将该路径规范化为 `/tmp/...`，而上游目录枚举使用 `O_NOFOLLOW_ANY`，因此拒绝 `/tmp` 符号链接组件。把同一工作树复制到非 `/tmp` 路径后，完整套件 33 项通过、0 失败；实际 DMG 的安装冒烟不受此测试路径限制影响。

## 未验证门禁

- 真实 push/PR GitHub Actions 运行、Actions artifact 下载和由下载文件安装的路径尚未在本轮产生证据。
- Intel Mac 实机与 macOS 13 实机运行仍未验证。x86_64 编译/链接通过不等于 Intel 实机通过，Rosetta 执行也不能替代 Intel 证据。
- 开发包只有 ad-hoc 签名且未公证；不得作为稳定版、已公证包或完整 alpha 验收结论。
- 直接位于 `/private/tmp` 的 worktree 会触发上述 `O_NOFOLLOW_ANY` 测试环境限制；这不替代 GitHub macOS runner 的正常项目路径，也不修改 T10 的来源或测试。
- 本机 runner image 为 `unknown / unknown`。workflow 固定 action commit SHA、`macos-14` label 和 Rust 1.99.0，并记录实际 `ImageOS`/`ImageVersion`、Swift/Xcode；Xcode 与 runner 精确镜像未被项目严格锁定，因此“完整可复现性”仍未验证。
