# T01：原生样本查询

对应 [GitHub #15](https://github.com/wynnok/fsearch-desktop/issues/15)。这是验证窗口，尚未启动或验证真实 `Engine`，不表示父 Spec-01、alpha 或发行验收完成。

## 构建和运行

在 macOS 项目根目录使用现有 Rust/Cargo 和 Swift/Xcode 工具链；不安装全局工具或切换版本。

```sh
bash scripts/dev.sh build
bash scripts/dev.sh run
bash scripts/dev.sh check
bash scripts/dev.sh test --filter FsearchServiceTests
bash scripts/dev.sh test
bash scripts/dev.sh ui-smoke
```

首次构建需要网络下载依赖。`bridge/Cargo.toml` 固定 Fsearch 0.2.1 的 commit `88e63fdf850cf7749deae8198b187accd21f8ba5`，`bridge/Cargo.lock` 锁定传递依赖；常规构建使用 `--locked`。`resolve` 仅供有意更新依赖锁时使用。

Cargo 下载和构建、SwiftPM 配置/安全目录/缓存、Clang/Swift 模块缓存和原生冒烟截图均在 `.build/`。上游代码与本项目桥接代码分离；没有上游补丁。上游 MIT 许可保留在 `bridge/FSEARCH-LICENSE`。

## 验证窗口

默认查询 `report`，Return 或“查询”按钮调用同一个动作。应看到 `report2.txt`、`report10.txt`；`笔记` 应找到 `笔记😀.md`；`^absent-fixture-name$` 显示无匹配；`re:[` 显示可恢复的查询失败。每行路径可与 `fixtures/sample/` 的真实文件核对。

本入口明确使用上游查询语法，普通词为模糊匹配。T02 才实现普通输入/高级语义的分离与更多跨语言安全验证；T03 实现完整快照/分页。窗口仅报告已载入条数和请求上限，不宣称匹配总数或全局排序。

## 最小公开契约

| 契约 | 语义 |
| --- | --- |
| `FsearchService(sampleDirectory:)` | 打开调用者指定的受控目录，构建内存样本索引；示例入口只使用项目内 `fixtures/sample/` |
| `SearchRequest(id, query, limit)` | UTF-8 上游查询语法、请求标识、1…1000 的结果上限（默认 50） |
| `search` | actor 串行执行 Rust 调用，异步调用者不会在主线程执行搜索；返回请求标识、值类型结果和状态，失败抛出明确错误 |
| `SearchResult` | UTF-8 绝对路径、类型（0 文件 / 1 目录 / 2 链接 / 3 其他）、索引大小、修改时间（Unix 秒）、上游相关度 |
| `ServiceStatus` | `mode=sample`、`ready=true`、`engineValidated=false`、精确上游版本；ready 仅指内存样本可查询 |
| `FsearchError` | 初始化、查询、桥接错误；错误后服务仍可继续查询 |

Rust 只调用上游 `walk::list_one`（单层、不递归）、`Index::build`、`Live` 和 `Searcher::search`。上游样本索引的虚拟根是 `/`，桥接仅将命中路径映射回真实样本目录；匹配、评分、索引格式和元数据编码均由上游实现。它没有持久索引、内容索引、全盘扫描、Engine 状态或变更通知；这些由后续 Tickets 验证。

C 输入字符串仅在调用期间借用，采用 UTF-8/NUL 结尾。创建成功的 opaque handle 由 Swift actor 私有持有，销毁时 `fsearch_sample_close`；同一 handle 不并发调用，不在查询中关闭。查询响应和创建失败的错误字符串由 Rust 分配，Swift 用 `defer` 调用 `fsearch_string_free`，复制为 Swift 值后不保留 Rust 指针。Rust 初始化/查询/关闭使用 `catch_unwind`；这不构成 T02 所要求的故障注入或资源增长验证。

样本查询的路径/范围语义仅适用于虚拟样本根，不代表实际 Engine 的范围搜索。默认启动入口无 Engine 调用，不读取用户 CLI 数据目录；后续真实 Engine 必须使用独立客户端索引并单独验证扫描边界。

TDD 首条查询测试先在未实现查询的桥接上失败，再接入 Searcher 通过；结果上限测试先复现无效请求被错误分类，再通过请求校验修正。空输入、无匹配和 Unicode 已由上游实现，因此追加回归核验而未人为制造失败。

原生 `ui-smoke` 实际启动窗口，经同一查询动作依次验证成功、无匹配、失败与 Unicode 恢复；四张截图在 `.build/native-smoke/`，已检查实际显示内容。沙箱内 LaunchServices 连接受限，原生冒烟在允许访问窗口服务的环境运行；之前阻塞的样本进程已结束。它不代替真实键盘/鼠标自动化、权限或安装包验收。
