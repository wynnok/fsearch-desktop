# T06：双架构构建和运行验证

对应 [GitHub #20](https://github.com/wynnok/fsearch-desktop/issues/20)，父规格 [SPEC-04](../specs/04-dual-architecture.md)。构建、链接、Rosetta、Intel 实机和 macOS 13 实测分别记录；跨编译成功不会解除实际设备门禁。

## 可复现入口

在项目根目录使用当前 Xcode/Swift 和 Rust 版本，无全局安装或默认工具链变更：

```sh
# 仅需首次准备额外 Rust target：复用当前精确稳定版，安装在 .build/rustup-home。
bash scripts/architecture.sh prepare
# 分架构构建 Rust staticlib、Swift 应用、最小原生 .app，再核验产物。
bash scripts/architecture.sh build all debug
bash scripts/architecture.sh service-test all debug
bash scripts/architecture.sh smoke all debug
# 最终发行配置可重复同样的验证；这里的 bundle 仅使用本地 ad-hoc 签名。
bash scripts/architecture.sh build all release
bash scripts/architecture.sh verify all release
```

架构参数可改为 `arm64` 或 `x86_64`。`build` 不隐式安装 Rust targets；未准备时会明确失败。`prepare` 将当前稳定版的精确版本安装到项目 `.build/rustup-home`，仅添加该隔离版本的两架构标准库；它不修改全局 `rustup default`、shell 配置、PATH 或原有工具链。工具链/依赖下载、构建缓存、SwiftPM 配置及安全目录、Clang/Swift 模块缓存、打包产物和验证日志均在 `.build/`。

`scripts/dev.sh` 保留原来的本机 `build/check/test/run/ui-smoke` 入口，并与双架构入口共享隔离缓存、Rust CPU 基线和部署目标。`Package.swift` 从 `FSEARCH_RUST_LIBRARY_DIR` 读取当前架构的静态库目录；直接调用 SwiftPM 仍兼容已有 `.build/rust/debug` 路径。

| 输出 | 位置 |
| --- | --- |
| arm64 Rust staticlib | `.build/rust/aarch64-apple-darwin/{debug,release}/libfsearch_bridge.a` |
| x86_64 Rust staticlib | `.build/rust/x86_64-apple-darwin/{debug,release}/libfsearch_bridge.a` |
| 每架构 Swift 缓存 | `.build/swift-{arm64,x86_64}-{debug,release}/` |
| 最小应用 | `.build/artifacts/{arm64,x86_64}/{debug,release}/FsearchSample.app` |
| 构建环境及哈希 | 同一产物目录的 `build-record.txt` |
| 架构/链接/部署核验 | 同一产物目录的 `artifact-check.txt` |
| 原生窗口启动日志/截图 | `.build/native-smoke/{arm64,x86_64}-{debug,release}/` |

## 兼容参数与产物核验

Rust 使用明确的 `--target`，arm64 的 CPU 基线为 `apple-a7`、x86_64 为 `x86-64`；入口覆写继承的 Rust flags，并清除 `CARGO_ENCODED_RUSTFLAGS`，不沿用上游 `target-cpu=native`。Swift 使用对应的 `arm64-apple-macosx13.0` / `x86_64-apple-macosx13.0` triple；两端均设置 `MACOSX_DEPLOYMENT_TARGET=13.0`。每架构链接独立的 Rust archive，Swift 缓存也分离。

`verify-artifact.sh` 在最终 `.app` 上检查 Rust archive 和主可执行文件的精确架构；检查 archive 所有对象及 bundle 所有 Mach-O 文件的最低 OS 不高于 13.0；检查 Info.plist 的最低系统 13.0、bundle 签名、主可执行文件的动态链接列表。Rust 静态内嵌；当前没有自带 dylib，剩余依赖必须是 `/System/Library/` 或 `/usr/lib/` 下的系统组件。未来加入内置 Mach-O 文件也会纳入切片和最低系统检查。

最小 bundle 包含受控样本文件及 Info.plist，使用本地 ad-hoc 签名；不构成公开签名、公证、DMG 或发行验收。`smoke` 直接启动 bundle 内对应架构的程序，并通过原生窗口的同一查询动作验证样本结果；它将请求架构、host 架构及系统版本记录在输出目录。Apple Silicon 上的 x86_64 启动明确记为 Rosetta，不记作 Intel 实机。

## 本轮验证记录

2026-10-13：当前主机 Apple Silicon arm64 / macOS 27.0.1，Rust 1.99.0，Swift 6.4，Xcode 27.0。初始全局仅安装 `aarch64-apple-darwin` 标准库。产物测试的首条红灯：尚未构建时，`verify arm64 debug` 因缺少对应 Rust archive 返回非零。

Fsearch 上游版本固定为 `88e63fdf850cf7749deae8198b187accd21f8ba5`，传递依赖由 `bridge/Cargo.lock` 锁定。最终产物的环境版本、锁文件/静态库/可执行文件 SHA-256 可从各架构 `build-record.txt` 复核。

本轮运行环境：Apple Silicon arm64、macOS 27.0.1、Rust 1.99.0、Swift 6.4、Xcode 27.0。项目内 `architecture.sh prepare` 已安装当前精确 Rust 版本的 arm64/x86_64 标准库，没有修改全局默认工具链。arm64 原生冒烟峰值 RSS 为 176,439,296 字节；该值是整个应用进程累计高水位，不是排序独占内存。
