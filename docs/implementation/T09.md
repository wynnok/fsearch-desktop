# T09：默认索引初建与空闲资源

对应 [GitHub #23](https://github.com/wynnok/fsearch-desktop/issues/23)。本票只提供维护者决策所需的真实资源证据；它不改变上游默认索引机制，也不把受控语料结果写成客户端性能承诺。

## 公开契约

新增 `FsearchResourceCheck`，三个模式都在独立进程中运行，输出结构化 JSON：

- `synthetic <corpusDir> <output.json>`：只通过 `FsearchService(sampleDirectory:)` 建立内存样本索引，记录冷/热查询、返回结果数和合成查询声明；不启动 Engine，不产生默认索引成本。
- `build <workspace> <output.json>`：通过 `FsearchService(confinedEngineDirectory:indexDirectory:)` 启动 T07 受限真实 Engine，测量到 `status.ready` 的时间，记录 ready 状态、内容处理状态、有限 warm 查询、`saveIndex` 请求和请求后的状态。
- `idle <workspace> <seconds> <output.json>`：在同一独立索引上启动 Engine，ready 后继续等待 `contentDocs > 0 && contentPending == 0`；只有收敛后才输出 `IDLE_READY` JSON 行并常驻。等待上限由 `FSEARCH_RESOURCE_IDLE_SETTLE_SECONDS` 配置，默认 180 秒；超时输出结构化 `IDLE_UNSETTLED`，其中记录超时时的 `contentDocs` 与 `contentPending`，并以非零退出。空闲期间不查询、不保存，结束后输出最终状态。脚本在进程外采样 CPU、RSS 和线程数。

退出码为 `0` 成功、`1` 测量或桥接失败、`2` 参数或路径拒绝。`synthetic` 的 corpus、真实模式的 workspace 和 output 均限制在项目根内，真实 workspace 必须在 `.build` 内；fixture 与 index 必须分离，`confinement-denied.txt` 必须存在。真实 Engine 一个进程只启动一次，完整停止仍以进程退出为准。

`scripts/index-resources.sh` 默认生成 20,000 个 512 字节文本文件，并分三段输出：

1. 样本服务合成查询；
2. 受限 Engine 首次扫描、内容状态收敛和有限 warm 查询；
3. 已有索引上的空闲进程，外部 `ps` 逐秒采样。

脚本在 `.build` 内使用 `mktemp` 保存本次 corpus、index 和中间文件，退出时只清理该 workspace，保留 `.build/engine-evidence/index-resources/report.json` 与 `report.md`。它不读取或修改用户/CLI 索引。

脚本开始测量前预检 `jq`、`stat`、`ps`、`du`、`mktemp`、`find`、`awk`、`grep`、`sed`、`sysctl`、`sw_vers`、Rust、Swift 和 Xcode 命令；缺失时以退出码 `2` 和明确的缺失列表失败，不生成不完整报告。报告记录实际 `jq --version`。macOS 自带 `/usr/bin/jq` 是否可用以该预检为准。

## 验证接缝

`IndexResourceTests.testSyntheticReportDoesNotClaimDefaultIndexCost` 先因 `FsearchResourceCheck` 不存在而失败；目标加入后，测试用项目 `.build` 内的真实三文件样本运行 `synthetic`，核对报告明确标记 `synthetic-sample`、`isDefaultIndexCost=false`、`isClientPerformanceGuarantee=false`，`defaultIndexCostSeconds` 为 `null`，并且 `resource` 查询返回真实样本的三个文件。测试不启动真实 Engine，避免 Seatbelt confinement 污染 XCTest 进程。

`IndexResourceTests.testResourceScriptRequiresSettledIdleBeforeFinalReport` 检查脚本契约：存在 `IDLE_UNSETTLED` 分支、空闲收敛环境变量，以及最终报告断言 build 内容收敛未超时、idle `contentSettled=true` 和至少一个外部采样。真实 idle 收敛必须在独立 Engine 进程中验证，不能由 XCTest 进程启动。

## 内容读取边界

v0.1 即使只展示名称入口，保留上游默认 Engine 时仍可能在后台读取符合规则的文本以维护内容索引。本次 20,000 个 `.txt` 文件均在受控 fixture 内被内容索引。首次 build 的 ready 状态可能先显示 `contentPending=0`、但 `contentDocs=0`，因此 build 实际等待 `contentPending == 0 and contentDocs > 0`；idle 只在该索引的 contentDocs 已达到 20,000 且 contentPending 为 0 后开始采样。

上游当前边界：内容索引从 `$HOME` 范围开始；非 Git 普通文本通常最多 1 MiB，无扩展名文本最多 256 KiB；Git 仓库多数文本最高约 10 MiB，但 JSON/JSONL/NDJSON 仍为 1 MiB。PDF、Word、Excel、PowerPoint、压缩包、图片等不做正文解码或 OCR。依赖、缓存、app/library bundle、部分 home 子目录、ignore 规则、生成文件及 minified/bundle 资产会排除；未覆盖范围回退扫描最多 200,000 个候选且单文件最多 1 MiB，因此不是全盘全文或不漏检保证。

## 上游选择

`Engine::Options` 当前没有索引根目录、禁用内容索引、暂停/取消、关闭或保存完成信号。若维护者认为初建、峰值内存或空闲后台成本不可接受，应优先推动上游提供索引根目录、内容索引开关/预算、暂停/取消、进度与完成信号，并保留可重复测量的升级门禁。不得复制内核、隐藏结果上限或用样本查询结果冒充默认索引和客户端保证。

## 未验证门禁

- 真实用户全盘 home 的初建时间、索引体积、峰值 RSS 和长期空闲成本仍未验证。
- 正式签名应用的 TCC/FDA 允许、撤销、重启及受保护位置真实结果仍未验证。
- iCloud 占位文件不物化、外接卷、Intel 实机、macOS 13 实机仍未验证。
- 本机 Debug 受控语料结果不能外推为 v0.1 客户端响应、覆盖完整性或内容索引完成时间保证。
