# T07：真实 Engine 独立索引与生命周期

对应 [GitHub #21](https://github.com/wynnok/fsearch-desktop/issues/21)。默认验证窗口仍使用样本 Searcher；真实 Engine 只能通过专用 `FsearchEngineCheck` / `--engine-smoke` 入口启动，避免普通开发运行误装进程限制或启动后台 Engine。

## 隔离策略

上游 `Engine` 没有 root 参数，首次索引会从 `/` 全盘枚举。验证入口在启动 Engine 前调用 macOS Seatbelt `sandbox_init`：允许读取指定 fixture、独立索引目录、必要系统运行库和路径祖先，拒绝其他 `file-read-data`。同时生成上游 `skip` 列表，排除 fixture 祖先下的所有同级路径，防止 FSEvents 递归列表绕过。启动前必须成功读取 fixture 旁边的 `confinement-denied.txt`，安装限制后再次读取必须失败；若任何证明失败，`Engine` 不会被启动。

索引目录由调用者指定在项目 `.build` 内，与上游 CLI 默认目录和既有进程分离。每个验证进程只允许一个 Engine；Engine 关闭句柄不声称释放后台线程或索引锁，完整停止由进程退出保证。该限制不可逆，因此专用入口使用独立进程而不是在常规测试进程里启动。

## 公开契约

`FsearchService(confinedEngineDirectory:indexDirectory:)` 是显式验证构造器，只应在专用进程使用。同一服务公开：

- `search`：真实 `Engine.search`，请求标识、结果、索引大小/修改时间和状态经 C ABI 返回；查询 scope 强制限定在 fixture 内。
- `status`：Engine 是否就绪、是否 owner、索引条数和内容待处理数；`ready` 不代表权限覆盖完整或所有内容处理完成。
- `changes`：同一服务交付的变更通知；这是目录失效信号，不是持久文件操作日志，最多保留最近 1024 条。
- `saveIndex`：请求上游保存名称索引。

保持上游默认名称与内容索引机制，本票不拆复制内容索引，不切换 helper，也不暴露正文搜索。Engine 查询通过真实 `Engine`，不是用 `Searcher` 通过替代。

## 验证

`bash scripts/engine-validation.sh` 在项目内创建临时 fixture 和索引，运行四个阶段并保留证据到 `.build/engine-evidence/`：

1. 首个进程启动受限 Engine，验证初始查询、目录新增、改名、修改、删除、公开 `changes`、保存和进程退出。
2. 第二个进程重新启动，加载保存索引并重新取得 owner 锁，查询恢复为完整快照。
3. 第三个进程在 owner 存活时以 follower 模式读取同一客户端索引，不获取第二个 writer 锁。
4. 原生窗口以 `--engine-smoke` 启动，执行真实 Engine 查询、关闭窗口、窗口关闭期间修改文件、等待通知与索引更新、重开查询、保存并退出应用。

2026-10-13 全部通过。首启日志显示索引 150 条；恢复进程加载 151 条并以 owner 运行；follower 读取同一索引且 `owner=false`；原生窗口输出 `engine-query` 和 `engine-reopened` 截图及退出日志。脚本只删除本次 `mktemp` 的项目内工作区，不触碰用户或 CLI 数据。

Debug 构建还在每个进程内注入真实 Engine worker panic，确认其被桥接为可恢复的 `bridge` 错误且不泄露私有查询内容；随后同一服务继续完成正常查询和生命周期验证。

未验证：真实用户磁盘授权/TCC 变化、云占位文件不物化、长时间空闲资源、正式签名应用权限、macOS 13 实机和 Intel 实机。这些门禁继续保留，不因受控 fixture 通过而解除。
