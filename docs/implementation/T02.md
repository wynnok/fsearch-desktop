# T02：普通名称、Unicode 与安全错误往返

GitHub：[TICKET-02](https://github.com/wynnok/fsearch-desktop/issues/16)，父规格 [SPEC-01](https://github.com/wynnok/fsearch-desktop/issues/2)。

## 服务契约

测试主接缝使用已确认的 Swift 公开 `FsearchService`。`SearchRequest` 保留 `id/query/limit`，新增默认 `.contains` 的 `SearchMode` 和默认 `false` 的 `collectAll`。普通模式将 Foundation 产生的 NFC/NFD 名称形式转义为公开 `Query.name_re`，由真实上游 `Searcher` 执行不区分大小写的名称包含匹配；冒号、空格、引号、换行、正则与通配字符都是名称数据。仅 `.advanced` 使用上游 `Query::parse` 查询语法。空白查询返回空集合，空标识、NUL 与非法 limit 返回可恢复查询错误；样本模式尚不支持文本内容查询，明确报错。

普通响应最多返回 `limit` 项（1...1000）；`collectAll` 将上游限制设为静态索引公开 `Index.n` 的条目上界。`isComplete` 来自该上界证据，不由已返回的条目数量推测，也不受上游解析器原来的 limit 范围影响。静态样本没有 overlay。错误响应的 `isComplete` 为 false。

为支持 T03 同名路径验证，样本加载从单层 `list_one` 升为上游 `walk::scan(明确样本根, 2)`，递归该根的子目录，结果虚拟路径映射回同一个样本根。没有 `scan_disk`、`Engine::start`、FSEvents 或个人磁盘扫描。上游扫描会提升当前进程的文件描述符软限制，不修改持久系统配置。权限拒绝与挂载点会遵守上游扫描行为；本票不将样本 readiness 声称为真实 Engine 生命周期或完整磁盘覆盖。`refreshSample()` 在 actor 内先重新创建同一根的句柄，成功后替换旧句柄，失败时保留原样本。

## 所有权与错误边界

C 输入 UTF-8 字符串只在调用期间借用；初始化错误和响应 JSON 属于调用者，Swift 每次用 `defer` 调用 `fsearch_string_free`。私有 `SampleHandle` 的 `deinit` 调用 `fsearch_sample_close`，释放 Rust Sample/Live/Index；actor 串行访问与刷新，不暴露指针。解码、请求标识校验或查询错误同样走释放路径。

初始化、搜索、关闭和字符串释放都进入 Rust unwind 捕获边界。正则解析错误被转换成固定消息，不输出用户查询、路径或正文。默认 panic hook 在 `catch_unwind` 之前可能打印 payload，因此使用一次安装的包装 hook 与 RAII 原子在途计数：桥接操作进行期间暂时抑制整个进程 Rust 工作线程的 panic payload，结束后继续调用原有 hook。取舍是同一期间无关 Rust 线程的 payload 也被抑制；没有永久关闭所有 panic 诊断，也没有修改主机设置。

实际故障注入仅通过 Debug/SPI `injectQueryPanic()`：专用 C 导出仅在 Rust debug 构建存在，在工作线程产生真正 panic，join 后恢复 unwind，由同一个搜索边界捕获为固定 `FsearchError.bridge`。生产查询没有 magic 字符串触发机制。测试断言该错误后普通搜索仍成功。

## Red → Green 证据

1. 名称标点：单测先失败两处（冒号被解释为筛选、通配字符匹配错误文件）；普通字面量模式后通过。
2. Unicode：NFC `café` 查询 NFD 样本先返回空而失败；Foundation 两形态传入公开 name regex 后通过，中文与 emoji 保留。
3. 请求/恢复：空标识、NUL、样本模式内容查询先未拒绝而失败三处；验证和固定错误后通过，每次错误后重新查询正常文件成功。
4. panic：公开 SPI 缺失时编译失败；增加显式 debug 入口后真正 panic 返回固定桥接错误，后续查询成功，无 payload 打印。
5. 递归：T03 的同名子目录测试先返回空（由并行 T03 代理记录）；使用受限根递归上游扫描后由 T03 重新验证。
