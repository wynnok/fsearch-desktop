# T31：内容范围、属性、正则与大小写选项

对应 [GitHub #45](https://github.com/wynnok/fsearch-desktop/issues/45)。固定上游为 `0.2.1 / 88e63fdf850cf7749deae8198b187accd21f8ba5`。

## 公开契约与映射

- `ContentSearchRequest` 增加 `mode`、`caseMode`、`scopePath`、`showsHidden` 与 `NameSearchFilters`。Swift 侧先校验空模式、NUL、文件限制、范围和过滤范围，非法正则仍由上游 `Grep::with_case` 返回可恢复错误，输入不会因失败被清空。
- bridge 的 `ContentRequest` 与名称查询共享 `apply_filters`，范围、kind、extensions、size、mtime 都映射到上游 `Query`；内容模式映射到 `GrepMode::Literal/Regex`，大小写映射到 `Case::Smart/Sensitive/Insensitive`。没有把内容 cursor 放进名称 offset。
- 关闭“显示隐藏项”时，隐藏 glob 在上游读取与 limit 之前进入候选 Query，避免隐藏命中占满页后被事后丢弃而误报完成。
- 正则编译、候选选择、文本准入和匹配算法继续由上游实现；客户端没有新增 PDF/Office/OCR、压缩包或自研解析。

## 界面

- 内容窗口提供普通文本/正则和智能/区分/不区分大小写选择，并复用名称窗口的范围、隐藏项与属性筛选组件。
- 改变模式、大小写、范围或筛选会立即丢弃旧响应和续查位置，避免旧结果冒充新条件；文件打开、Quick Look、Finder 与复制路径动作保持不变。

## 验证

- `ContentSearchOptionsTests` 核对公开 JSON 契约和错误后可修正状态。
- 真实受限 Engine 的 `ContentCheck` 使用受控 fixture 验证 literal 不解释 `.`、regex `a[.]b|axb`、smart/sensitive/insensitive、scope+extension+size+hidden 过滤、无匹配和非法正则后继续查询。
- `bash scripts/dev.sh check` 与 `bash scripts/dev.sh test --filter ContentSearchTests` 通过；后者在非沙箱独立进程内安装 Seatbelt。

## 边界

T31 只覆盖文本准入/忽略/大小规则所允许的查询，不承诺未索引位置穷尽。直接扫描仍有上游候选与大小限制；云端未下载正文不可搜，Quick Look 能力不扩展正文检索范围。
