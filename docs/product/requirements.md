## 产品定位

独立的 macOS 文件搜索应用，核心任务是“知道名字或部分线索，迅速找到文件”。面向普通用户，默认使用可视化配置，无需理解查询语法、终端或 Rust。搜索和索引完全基于 Fsearch；Finder 用于打开位置，不承担搜索能力。

工作名暂用 Fsearch Desktop；正式名称、图标和品牌在 beta 前确定，不影响技术验证。
Everything 是使用体验参考，不是已达成的速度、索引覆盖或特性承诺。Scherlokk 截图只用于理解区域分工。

用户已确认文本内容搜索按 v0.2 beta 交付；首版设计预留入口与状态语义。文本 grep 不包装成任意文档全文检索。

版本范围描述用户可用功能，并不等于引擎内部只构建对应索引。用户已确认首版保留上游默认后台索引机制；当前 Engine 没有公开关闭内容索引的选项，可能读取符合规则的文本并建立内容索引。初建、内存与后台资源必须实测，若不合格优先推动上游控制选项；不得承诺“首版仅建立名称索引”。

空输入且未设置有效筛选条件时展示搜索提示，不启动全量结果查询或排序；这不影响 Fsearch 索引自身的初始化和维护。用户可以仅设置类型、大小或时间等筛选进行查询，默认范围和隐藏项设置不单独触发全量查询。

## 不可绕过的引擎边界

详细证据见[引擎调查](../research/fsearch-engine.md)。

- 原始 JSON API 无全局 sort、total，名称分页取数最多检查 20,000 条。不能在这个接口之上声称实现了任意规模的全局排序。
- 直接调用 crate 能设置更大的 Query.limit，但全匹配集合的内存、延迟和并发代价需要技术验证，不能依据上游 top-k 基准推出它同样快。
- 基底索引在文件小于 2 GiB 时保存精确大小，达到 2 GiB 后按 2 MiB 粒度向下编码。精确大小显示可按需读元数据，但字节级严格筛选可能先在上游筛选阶段遗漏边界候选；若需要这种精度，必须走上游改进，不能仅靠客户端补读就宣称修复。
- Fsearch 初始扫描不跨挂载点；外接硬盘、网络卷及指定这些位置的范围不能直接承诺支持。需求存在时先走上游能力验证或贡献。
- 持久文本索引主要在 home 内，受大小、类型和排除规则约束。PDF、Office、压缩包正文、OCR 不在本产品基于当前上游的能力内。
- 无完全磁盘访问权限时，Desktop、Documents、Downloads 等位置可能被主动跳过。授权后还需要重新检查覆盖，不能仅隐藏提示。
- iCloud 占位文件不会因索引而被自动下载；本地缺失的正文不能显示为已搜索。
- 上游没有文件名匹配位置 API。模糊匹配高亮不能由客户端猜测后当成引擎精确证据。
- 文件名包含空格、冒号、引号、换行和中文时，普通模式应以结构化字段传给适配层，不拼接成高级查询语法。

用户已接受首版采用索引大小进行筛选和全局排序，检查器提供实际大小。大小精度差异是已公开的产品语义，不将近似结果标成字节级精确结果；排序验收按此契约进行。

## 体验目标与验证口径

以下是候选验收目标，不是性能实测：名称查询到首屏 warm p95 ≤ 150ms（包含 UI 和桥接），连续键入无主线程卡顿；在 1M / 8M 项规模分别记录冷启动、首次索引、全局排序、RSS 峰值和空闲 CPU。全局排序可比 top-k 更慢，需有查询中状态和取消/丢弃过期响应机制。

输入延迟初值建议 100–150ms，实际值在验证后调整。旧请求晚返回不能覆盖新输入；无结果与索引未就绪必须不同。大结果集合只向 UI 交付可见页，不允许一次渲染全部结果。

发布前必须覆盖中文、组合/分解 Unicode、大小写、emoji、长路径、同名文件、符号链接、应用包、文件消失、权限拒绝和持续变更场景。上游说明中的重音处理不等于中文分词或拼音检索；这两项目前没有支持承诺。

名称自然排序验收需包含 `文件2` / `文件10`、中文、大小写、重音和相同名称；采用原生排序语义，同值以路径稳定区分。自然排序只改变结果呈现，不修改 Fsearch 的匹配算法。仅隐藏项筛选和系统文件可见性也不能悄悄改变索引覆盖。

## 最终共同理解与下一阶段

本轮访谈收敛 v0.1 产品行为、引擎集成约束和持续跟进上游的流程。v0.2 文本内容搜索的具体交互、后续品牌与自动下载安装在各自阶段继续细化，不扩展首版范围。

独立 macOS 原生应用以 Fsearch 为唯一搜索与索引引擎，优先通过公开 Rust Engine 加薄 C ABI 集成；允许可撤销的必要补丁，保持上游升级通路。v0.1 交付真实名称搜索、筛选、完整集合排序、检查器、Quick Look 和 Finder 路径操作；支持目标为 macOS 13+，两种芯片功能一致。后台默认索引行为与大小精度限制按已确认规则公开说明。

M1 先验证技术可行性，再进入 alpha 界面实现；清单见 [M1 验证计划](../engineering/validation-plan.md)，执行规格见 [Spec 索引](../specs/README.md)。代码、工作流、安装包和 M1 实测结果目前均未产生，文档中的已确认决定不等于已实现能力。本次授权为规格拆分和 GitHub Issues 发布，不替代实际测试、签名凭据准备或后续明确的 Git 提交/推送指令。
